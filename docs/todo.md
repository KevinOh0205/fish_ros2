## 1. 코드 결함 수정 — 물 없이 지금 가능 **[나]**

11개 에이전트 독립 검증에서 나온 것. 부호와 지연은 통과했고, 아래는 그 외 결함이다.

- [x] ~~**대기압 영점에서 q 영점(Δb)을 함께 채우기**~~ — **완료 2026-08-25**
      검증: 잡음 주입 상태에서 `Δb = 0.7123 mbar` (기대 0.720), flags `0x21F`, 파일에 `q_from_air=1`
      q 영점이 없으면 **정지 상태에서 0.394 m/s 를 읽는다**(센서 개체차 Δb = 0.775 mbar 실측).
      그런데 **공기 중 차압이 곧 Δb 다** — 공기가 물보다 828배 가벼워 기울기 효과가
      20°에서도 0.007 mbar(잡음의 1/27)라 사실상 0이기 때문이다.

      그리고 **그 데이터가 이미 있다.** 대기압 영점이 세 채널 101샘플을 모으므로
      `Δb = ch_front − (ch_left + ch_right)/2` 뺄셈 한 번이면 된다.
      오늘 실측: `1005.38 − (1005.88 + 1003.44)/2 = +0.72 mbar`

      **물속 q 영점이 이미 있으면 덮어쓰지 않는다** — 물속 값은 기하 모델 오차까지
      흡수하므로 더 좋다. 역할이 갈린다:
        · 공기 Δb (자동, 켤 때마다) → 센서 개체차만. 남는 오차 = 기하 모델 오차
        · 물속 q 영점 (btn, 선택)   → 모델 오차까지 흡수. 단 **그 자세에서만**
      기울기 시험으로 `lever_x`가 정확해지면 **공기 영점만으로 물속 영점과 거의 같아진다.**

      부수 효과: 기울기 시험에서 `lever_z`와 Δb 가 축퇴되는데(`cos θ`가 ±20°에서 6 %만
      변한다), Δb 를 따로 알면 그 축퇴가 풀린다. 즉 보정 분석에도 필요한 값이다.

## 2. 결정이 필요한 것 — 답을 주면 바로 구현 **[사람 → 나]**

- [x] ~~**q 영점을 어떤 제스처로 걸 것인가**~~ — **완료 2026-08-25: 새 제스처도, 물속 분기도 없음**
      `btn1 3초` = **대기압 영점 (+ 공기 Δb 자동 충전), 공기 중 전용.**
      물속 q 영점은 버튼에 얹지 않는다 — 4장에서 오차가 실제로 보였을 때만 쓰는
      선택 사항이라, 버튼에 두면 잘못 눌렀을 때 쓸모없는 실패 로그만 쌓인다.
      필요하면 `ros2 service call /hydro/zero_q std_srvs/srv/Trigger`.
      **잠김 확인만 남긴다** — `게이지압 > 5 mbar` 면 거부. 지우면 안 되는 이유는
      얕게 잠긴 채 누르면 그 깊이가 `[900,1100]` 타당성 게이트를 **통과해** 대기압으로
      박히고 세션 내내 수심이 그만큼 어긋나기 때문이다(실측: 8 mbar → 8 cm 그대로 침투).
      문턱 5 mbar 근거는 **공기 중 게이지압의 상한**이다: 기압 표류가 하루 최악 3.4 mbar 인데
      `atm_zero_max_age_sec`(하루)가 그보다 묵은 영점을 아예 안 실으므로 공기 중에서
      3.4 를 넘을 수 없다. 정말 공기 중인데 거부당하면 `/hydro/zero_atm` 으로 우회.
      검증(발행자 1개 확인 후): 0.00 통과 · 3.00 통과 · 8.00 거부 · 29.30 거부

- [x] ~~**공기 중 Δb 측정 모드를 넣을 것인가**~~ — **결정 2026-08-25: 넣는다**
      별도 모드가 아니라 **대기압 영점에서 자동으로 함께 채운다.** 구현은 1장 참조.
      근거: q 영점이 없으면 정지에서 0.394 m/s 를 읽는데, 공기 중 차압이 곧 Δb 이고
      그 데이터가 이미 모여 있다. "일단 공기로 하고 물에서 확인 후 필요하면 고친다" —
      **되돌릴 수 있는 결정**이라 안전하다: `Q_raw`와 `Hydro_Pitch`가 CSV에 남으므로
      나중에 영점·기하가 틀렸다고 판명나도 **그 주행을 오프라인에서 다시 계산**할 수 있다.
      확인 방법은 4장의 "정지 상태에서 Speed 읽어보기" 참조.

- [ ] **q 영점 게이트에 자이로 정지 판정을 넣을 것인가**
      지금은 압력 산포로 간접 판정한다. 자이로를 보면 손으로 들고 있는 상태를 직접 잡는다.
      단 **일정한 느린 표류는 어떤 센서로도 못 잡는다**(원리적 한계) — 진짜 방어는 절차다

- [x] ~~**로거 보관 개수 제한을 넣을 것인가**~~ — **결정 2026-08-25: 넣지 않는다. 사람이 관리**
      자동 삭제는 `log_csv/`에 실험 CSV·보정 파일이 같이 살아서 늘 위험이 따른다.
      대신 관리에 필요한 사실만 적어둔다:

      | | |
      |---|---|
      | 쌓이는 속도 | **시간당 약 99 MB** (47열 기준) |
      | 4일 방치하면 | 약 **9 GB** |
      | 파일 회전 | 200 MB마다 (약 2.0시간) |

      **가장 확실한 방법은 안 쓸 때 서비스를 내리는 것** — `sudo systemctl stop fish-robot`.
      로봇이 벤치에 있는 동안은 아무것도 기록할 게 없다(실제로 4일치 7.3 GB가 전부
      조종기 0행·AUTO 0행·모터 0행이었다).

      지울 때:
      ```bash
      cd ~/ros2_ws/log_csv
      ls -lt fish_log_*.csv          # 최근 것부터 확인
      rm fish_log_2026082*.csv       # **접두사 fish_log_ 만** 지운다
      ```
      **남겨야 하는 것**: `mag_calib_params.txt`(EKF가 실제로 읽는 활성 파일),
      `hydro_zero.txt`, `port_map.txt`, 그리고 실험 CSV(`allan_`, `presschar_`,
      `spin360_`, `tumble_`, `bench_`) — 이들은 문서화된 측정의 유일한 원본이다.

      ※ 지우기 전에 활동이 있었는지 30초면 확인된다:
      ```bash
      awk -F, 'NR>1{n++; if($8!=-9999)rc++; if($4==1)a++; if($15!=1000)m++} \
               END{printf "행 %d, 조종기 %d, AUTO %d, 모터 %d\n",n,rc+0,a+0,m+0}' 파일.csv
      ```
      네 숫자가 `행 N, 0, 0, 0` 이면 아무 일도 없었던 파일이다.

## 4. 욕조에서 할 것 **[사람 + 나]**

물 깊이 **약 40 cm**면 된다(20° 기울일 때 앞 포트가 ±6 cm 움직이므로). 수영장 불필요.
흐름이 없어야 하고, 로봇을 손으로 고정할 수 있으면 된다.

- [ ] **부호 최종 검증** ← 이게 통과 못 하면 나머지가 무의미
      코를 20° 숙였을 때 `P_hydro`가 **+5.885 mbar로 커지고** `Q_dyn`은 **변하지 않아야** 한다.
      `Q_dyn`이 피치를 따라 움직이면 부호가 반대다(오차가 2배로 들어간다).
      기동 배너는 **계산의 부호**만 확인해준다. 물리가 맞는지는 여기서만 확인된다

- [ ] **기울기 시험 → `lever_x`, `lever_z` 역산**
      5개 피치각(±20° 범위)에서 정지 측정 → `q_raw`를 `sin θ`와 `cos θ`에 회귀.
      **기울기 ÷ 17.208 = 실효 `lever_x`**, `cos θ` 항 = `lever_z`(Δb를 미리 알아야 분리됨).
      자로 잰 17.6 cm를 그대로 안 쓰는 이유: 실제 압력이 걸리는 지점이 구멍 위치와 다르다

- [ ] **정지 상태에서 `Speed` 읽어보기 — 30초짜리 확인 두 번**
      물속에 가만히 띄워놓고 `Speed`를 본다. 정지니까 0이 나와야 하고, 안 나오면
      그 크기가 곧 오차다. **두 자세를 다 봐야 한다** — 각각 다른 것이 드러난다:

      **② 수평으로 띄우고** → **포트 높이차**가 드러난다 (`cos 0 = 1` 이라 최대로 보임)

      | 앞 포트 높이차 | 정지인데 읽히는 값 |
      |---|---|
      | 0.5 cm | 0.313 m/s |
      | 1.0 cm | 0.443 m/s |
      | 2.0 cm | 0.626 m/s |

      **1.2 mm 만 어긋나도 보인다.** 크면 `lever_z`를 재거나 물속 q 영점을 잡는다.

      **③ 10~20° 기울이고** → **`lever_x` 오차**가 드러난다 (수평에서는 `sin 0 = 0` 이라 안 보임)

      | `lever_x` 오차 | 정지인데 읽히는 값 |
      |---|---|
      | 2 % | 0 (데드밴드 안) |
      | 5 % | 0.173 m/s |
      | 10 % | 0.245 m/s |

      **4 %를 넘으면 보인다.** 크면 아래 기울기 시험으로 역산한다.

      **②③이 둘 다 0 근처면 정밀 보정을 건너뛰어도 된다.**

- [ ] **물속 q 영점** — 잔잔해진 뒤 잡는다. 위 ②③에서 오차가 보였을 때만 필요하다
      (공기 Δb 가 자동으로 채워지므로 속도는 그전에도 나온다)

- [ ] **수심 자로 대조** — 30 cm에서 ±1 cm 이내

- [ ] **기포 확인** — 정체압 포트에 공기가 갇히면 오프셋 + 굼뜬 반응.
      **첫 습식 시험의 가장 유력한 실패**다. 퍼지 절차를 정할 것

## 5. 주행에서 할 것 **[사람 + 나]**

직선 몇 미터가 필요하다. 4장이 끝나고 파라미터가 들어간 뒤에 한다.

- [ ] **`speed_k` 확정** — 표시한 거리(예: 5 m)를 **자력 주행**하며 스톱워치
      **예인으로 하면 안 된다.** 끌 때는 몸이 안 흔들려 정체압이 온전한데, 실제 유영은 좌우로
      흔들려 정체압이 `cos²β`만큼 깎인다. 예인으로 맞춘 배율은 운용에서 속도를 1~3 % 낮게 만든다

- [ ] **꼬리치기 피치 진폭 측정** ← `pressure_lag_ms` 작업의 **선결 조건**
      지연 오차는 **주기 운동에서 평균이 정확히 0**이라(같은 신호를 시간 이동한 것의 차이),
      τ=1초 저역통과가 2 Hz를 12.6배 감쇠시킨다. 그래서 **정상 순항에서는 거의 문제가 안 된다**:

      | 꼬리치기 | 순간 오차 | τ=1s 필터 후 | v=1.0에서 |
      |---|---|---|---|
      | 2 Hz 진폭 3° | 0.787 mbar | 0.063 | +0.62 % |
      | 2 Hz 진폭 10° | 2.615 | 0.208 | +2.06 % |

      **진폭을 재기 전에는 지연을 정밀하게 맞출 이유가 없다.** 1°면 무시, 10°면 필요 —
      10배 차이다. 조립 후 CSV의 `Hydro_Pitch`로 바로 뽑을 수 있다.

- [ ] **`pressure_lag_ms` 확정** — 위 진폭이 크게 나왔을 때만 한다.
      제자리에서 꼬리를 치며 기록한 뒤 오프라인에서 지연을 훑어 `corr(Q_dyn, sin θ)`를
      최소화하는 값. 기본 72에서 출발. **정지 로그로는 검증 불가** — 72 ms가 만드는 차이가
      0.000007°라 잡음에 묻힌다. ω ≳ 20 °/s로 흔들어야 한다.

      ※ **기동 중(비주기)에는 평균이 0이 아니다.** 피치 20 °/s로 지속 회전하면 0.432 mbar가
      편향으로 박혀 v=0.6에서 **+11.4 %**다. 그리고 `τ`를 1초에서 0.3초로 줄이면
      감쇠가 12.6 → 3.8배로 떨어져 되살아난다

- [ ] **PID 게인 튜닝** — 지금은 벤치 추정치(`kp` 3.5/3.5/1.2, `ki`=`kd`=0).
      물의 감쇠·관성이 공기와 완전히 다르다. `ki`를 살릴지도 여기서 결정
      ※ `ki`나 `kd`를 살리는 순간 **`dt` 생략 문제가 진짜가 된다**(지금은 P 단독이라 무해)

- [ ] **`roll`/`pitch` 오프셋 결정** — 장착 기준 7.9°가 보정 없이 남아 있어,
      PID에 "pitch 0"을 주면 로봇은 **7.9° 기운 상태를 수평으로 여긴다.**
      중성부력 자세와 얽혀 있어 물에 띄워봐야 정해진다

- [ ] **꼬리치기 pitch 편향 측정** — 조립 후에만 가능
