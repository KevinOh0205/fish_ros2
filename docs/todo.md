## 1. 코드 결함 수정 — 물 없이 지금 가능 **[나]**

11개 에이전트 독립 검증에서 나온 것. 부호와 지연은 통과했고, 아래는 그 외 결함이다.

- [ ] **정압 포트 하나 죽었을 때 롤 보정 누락**
      좌우 평균은 측정점이 롤 축 위(중점)라 롤이 상쇄되는데, 한쪽이 죽으면 측정점이 4.4 cm
      벗어난다. 그런데 `lever_y = 0`을 계속 쓴다. 롤 30°에서 **2.13 mbar 누락 — v=0.6이 0.887로
      읽힌다(+48 %)**. 게다가 `FLAG_SPEED_OK`가 그대로 켜져 로그로도 모른다.
      → 살아남은 포트 위치를 실효 `lever_y`로 넣고, 속도 신뢰도 저하 플래그를 세운다.

- [ ] **`half_span_` 파라미터가 어디에도 안 쓰인다**
      선언하고 기동 로그에 찍기만 한다. 위 항목을 고치는 데 필요한 바로 그 값인데 배선이 없다.
      지금은 로그에 `좌우반경 0.044 m`가 찍혀 **거짓 안심**을 준다. (위와 같은 수정)

- [ ] **q 영점이 10분 만에 버려진다**
      영점 파일 유효기간 600초를 대기압 영점과 **한 덩어리로** 적용한다. 대기압에는 맞는 이유
      (날씨가 시간당 1~2 hPa)지만 **q 영점은 차압이라 날씨가 상쇄된다** — 3.87일 실측에서
      10분~6시간 내내 σ 0.053 mbar로 평평했다. 코드 주석이 "하루를 가도 유효"라고 적어놓고도
      버린다. **잠수 중 respawn 되면 속도가 NaN이 된다.**
      → 유효기간을 둘로 분리 (대기압 600초, q 하루)

- [ ] **지연 부호가 틀리면 조용히 무보정으로 퇴화한다**
      `attitude_at()`이 버퍼 범위 밖이면 끝값으로 포화시키고 `true`를 반환한다. 부호를 `+`로
      잘못 쓰면 **항상 최신 자세를 쓰게 되어 무보정과 동일**해지는데 `FLAG_ATT_FRESH`는 켜진다.
      오차가 2배가 아니라 1배로 되돌아가는 것이라 훨씬 잡기 어렵다. 꼬리치기 중 속도가
      7~12 % 진동하는데 원인을 못 찾게 된다.
      → 포화가 일어나면 별도 플래그. 정상 동작에서는 절대 포화하지 않는다(버퍼 0.64초 vs 지연 0.072초)

- [ ] **배정 뒤바뀜 감시가 너무 둔하다**
      필터링된 q에 **원시 σ** 문턱을 쓴다. 실제로는 14σ에 해당해서
      **−0.16 ~ −0.34 m/s의 역주행을 영원히 못 잡는다.** → 필터 후 σ를 쓴다.

- [ ] **자세 폴백 상태에서도 q 영점을 잡는다** — 상수 피치로 계산한 값이 영점으로 박힌다.
      → `FLAG_ATT_FALLBK`면 거부

- [ ] **q 수집에 타임아웃이 없다** — 압력이 끊기면 영구 대기. → 30초 타임아웃 + 로그

## 2. 결정이 필요한 것 — 답을 주면 바로 구현 **[사람 → 나]**

- [ ] **q 영점을 어떤 제스처로 걸 것인가**
      물속에서는 터미널을 못 쓰므로 조종기로 걸 수 있어야 한다.
      - **btn1+btn2 동시 3초** (추천) — 우발 발동 거의 없음, 세지 않아도 됨
      - btn1 5번 클릭 — **btn1 짧은 누름이 AUTO 토글이라 5번이면 모드가 5번 뒤집힌다.**
        쓰려면 토글을 0.5초 지연시켜야 함
      **→ 확인 필요: 조종기에서 두 버튼을 동시에 누를 수 있는 배치인가?**

- [ ] **공기 중 Δb 측정 모드를 넣을 것인가**
      공기 중 차압이 곧 센서 개체차 Δb다(공기는 물보다 828배 가벼워 기울기 효과가 무시된다).
      **물속 기울기 시험에서 `lever_z`와 Δb가 축퇴**되므로(cos θ가 ±20°에서 6 %만 변한다),
      Δb를 공기에서 따로 재두면 그 축퇴가 풀린다. → **넣는 쪽을 권함**

- [ ] **q 영점 게이트에 자이로 정지 판정을 넣을 것인가**
      지금은 압력 산포로 간접 판정한다. 자이로를 보면 손으로 들고 있는 상태를 직접 잡는다.
      단 **일정한 느린 표류는 어떤 센서로도 못 잡는다**(원리적 한계) — 진짜 방어는 절차다

- [ ] **로거 보관 개수 제한을 넣을 것인가**
      4일 방치에 **7.3 GB**가 쌓였고 전부 무활동이었다. 접두사로만 지우면 실험 CSV와
      보정 파일은 안전하다. 대안: 안 쓸 때 서비스를 내린다

## 4. 욕조에서 할 것 **[사람 + 나]**

물 깊이 **약 40 cm**면 된다(20° 기울일 때 앞 포트가 ±6 cm 움직이므로). 수영장 불필요.
흐름이 없어야 하고, 로봇을 손으로 고정할 수 있으면 된다.

- [ ] **부호 최종 검증** ← 이게 통과 못 하면 나머지가 무의미
      코를 20° 숙였을 때 `P_hydro`가 **+5.885 mbar로 커지고** `Q_dyn`은 **변하지 않아야** 한다.
      `Q_dyn`이 피치를 따라 움직이면 부호가 반대다(오차가 2배로 들어간다).
      기동 배너는 **계산의 부호**만 확인해준다. 물리가 맞는지는 여기서만 확인된다

- [ ] **기울기 시험 → `lever_x`, `lever_z` 역산**
      5개 피치각(±20° 범위)에서 정지 측정 → `q_raw`를 `sin θ`와 `cos θ`에 회귀.
      **기울기 ÷ 17.208 = 실효 `lever_x`**, `cos θ` 항 = `lever_z`(Δb를 미리 알아야 분리됨).
      자로 잰 17.6 cm를 그대로 안 쓰는 이유: 실제 압력이 걸리는 지점이 구멍 위치와 다르다

- [ ] **물속 q 영점** — 잔잔해진 뒤 잡는다

- [ ] **수심 자로 대조** — 30 cm에서 ±1 cm 이내

- [ ] **기포 확인** — 정체압 포트에 공기가 갇히면 오프셋 + 굼뜬 반응.
      **첫 습식 시험의 가장 유력한 실패**다. 퍼지 절차를 정할 것

## 5. 주행에서 할 것 **[사람 + 나]**

직선 몇 미터가 필요하다. 4장이 끝나고 파라미터가 들어간 뒤에 한다.

- [ ] **`speed_k` 확정** — 표시한 거리(예: 5 m)를 **자력 주행**하며 스톱워치
      **예인으로 하면 안 된다.** 끌 때는 몸이 안 흔들려 정체압이 온전한데, 실제 유영은 좌우로
      흔들려 정체압이 `cos²β`만큼 깎인다. 예인으로 맞춘 배율은 운용에서 속도를 1~3 % 낮게 만든다

- [ ] **`pressure_lag_ms` 확정** — 제자리에서 꼬리를 치며 기록한 뒤,
      오프라인에서 지연을 훑어 `corr(Q_dyn, sin θ)`를 최소화하는 값. 기본 72에서 출발.
      **정지 로그로는 검증 불가** — 72 ms가 만드는 차이가 0.000007°라 잡음에 묻힌다.
      ω ≳ 20 °/s로 흔들어야 한다

- [ ] **PID 게인 튜닝** — 지금은 벤치 추정치(`kp` 3.5/3.5/1.2, `ki`=`kd`=0).
      물의 감쇠·관성이 공기와 완전히 다르다. `ki`를 살릴지도 여기서 결정
      ※ `ki`나 `kd`를 살리는 순간 **`dt` 생략 문제가 진짜가 된다**(지금은 P 단독이라 무해)

- [ ] **`roll`/`pitch` 오프셋 결정** — 장착 기준 7.9°가 보정 없이 남아 있어,
      PID에 "pitch 0"을 주면 로봇은 **7.9° 기운 상태를 수평으로 여긴다.**
      중성부력 자세와 얽혀 있어 물에 띄워봐야 정해진다

- [ ] **꼬리치기 pitch 편향 측정** — 조립 후에만 가능

## 다 끝나지 않는 것

- **지자기 보정은 조립이 바뀔 때마다 무효**다. 하우징을 닫으면 하드아이언이 통째로 바뀐다
  (지난 조립 때 (−12.3, +23.5, −89.8) → (+9.9, +61.6, −16.1) µT)
- **로그 총량은 사람이 관리**한다. 시간당 99 MB(47열 기준)
- **`SERVO_MIN_US`/`MAX_US`(1250/1750)는 nRF 펌웨어와 맞춰야** 하는데 이 저장소가 강제할 수 없다
