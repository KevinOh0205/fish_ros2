## 2. 욕조에서 할 것 **[사람 + 나]**

물 깊이 **약 40 cm**면 된다(20° 기울일 때 앞 포트가 ±6 cm 움직이므로). 수영장 불필요.
흐름이 없어야 하고, 로봇을 손으로 고정할 수 있으면 된다. 넣기 전 **기포 퍼지**부터.

- [ ] **기포 확인·퍼지 절차 확정** — 정체압 포트에 공기가 갇히면 오프셋 + 굼뜬 반응.
      **첫 습식 시험의 가장 유력한 실패다.** 물속에서 노즈를 아래로 기울이거나 흔들어 빼고,
      `q`가 꼬리치기 시작에 즉각 따라오는지로 판정. 절차가 정해지면 operation.md 4장에 반영

- [ ] **부호 최종 검증** ← 이게 통과 못 하면 나머지가 무의미
      코를 20° 숙였을 때 `P_hydro`가 **+5.885 mbar로 커지고** `Q_dyn`은 **변하지 않아야** 한다.
      `Q_dyn`이 피치를 따라 움직이면 부호가 반대다(오차가 2배로 들어간다).
      기동 배너는 계산의 부호만 확인해준다 — 물리는 여기서만 확인된다

- [ ] **정지 상태에서 `Speed` 읽어보기 — 30초짜리 확인 두 번**
      정지니까 0이 나와야 하고, 안 나오면 그 크기가 곧 오차다. 두 자세가 각각 다른 것을 드러낸다:

      **① 수평으로 띄우고** → **포트 높이차** (`cos 0 = 1` 이라 최대로 보임)
      | 앞 포트 높이차 | 정지인데 읽히는 값 |
      |---|---|
      | 0.5 cm | 0.313 m/s |
      | 1.0 cm | 0.443 m/s |
      | 2.0 cm | 0.626 m/s |

      **② 10~20° 기울이고** → **`lever_x` 오차** (수평에선 `sin 0 = 0` 이라 안 보임)
      | `lever_x` 오차 | 정지인데 읽히는 값 |
      |---|---|
      | 2 % | 0 (데드밴드 안) |
      | 5 % | 0.173 m/s |
      | 10 % | 0.245 m/s |

      **①②가 둘 다 0 근처면 아래 정밀 보정(기울기 시험·물속 q 영점)을 건너뛰어도 된다.**
      ※ 이상하면 ch2(우현)부터 의심 — 오프셋이 계단으로 뛴 전력이 있는 개체다(5장)

- [ ] **기울기 시험 → `lever_x`, `lever_z` 역산** (위에서 오차가 보였을 때만)
      5개 피치각(±20° 범위)에서 정지 측정 → `q_raw`를 `sin θ`와 `cos θ`에 회귀.
      **기울기 ÷ 17.208 = 실효 `lever_x`**, `cos θ` 항 = `lever_z`(공기 Δb를 알아서 분리 가능).
      자로 잰 17.6 cm를 안 쓰는 이유: 실제 압력이 걸리는 지점이 구멍 위치와 다르다

- [ ] **물속 q 영점** (위에서 오차가 보였을 때만) — 잔잔해진 뒤
      `ros2 service call /hydro/zero_q std_srvs/srv/Trigger` (3초 수집, 꼬리·흐름 정지)

- [ ] **수심 자로 대조** — 30 cm에서 ±1 cm 이내

## 3. 주행에서 할 것 **[사람 + 나]**

직선 몇 미터가 필요하다. 2장이 끝난 뒤에 한다.

- [ ] **PID 게인 튜닝** — 전부 런타임 파라미터라 재빌드 없이 물가에서 바로 돈다.
      진입 전 확인 2건: 실부하에서 `ros2 topic hz /filtered/attitude` ≈ 100 Hz,
      발행자 1개. **튜닝 중 btn2 길게(지자기 보정) 금지** — CPU 를 잡아먹어 100 Hz 를 흔든다.
      축별로 (pitch → roll → yaw):
      1. **kp: 소진폭 스텝 응답으로** — 목표 ±3~5° 스텝, 오버슈트 <20 % 까지 올린다.
         ※ 임계진동(ku) 탐색은 부적합 — kp 8.75가 이미 오차 20°에서 창 포화라, 발진 전에
         포화가 먼저 걸려 릴레이형 리밋사이클을 ku 로 오측한다
      2. **ki: 정상상태 오프셋이 남을 때** 0.01부터. **함정: 최대 I 기여 = i_limit × ki**
         (기본 300 × 0.01 = 3 µs 뿐). 목표 오프셋보다 작으면 i_limit 도 같이 키울 것
      3. **kd: 오버슈트가 남을 때만.** 현재 D 는 원시 차분이라 잡음 증폭 + 목표 스텝 킥.
         실제로 켜게 되면 그때 → **[나]** 측정값 미분 + 1차 필터로 변경
      4. AUTO↔MANUAL 전환은 적분을 리셋하지 않는다 — 전환 직후 ki 를 같은 값으로
         `param set` 하면 리셋된다(부수효과 활용). 근본 수정은 5장
      ※ `ki`/`kd`는 dt 흡수형이라 **100 Hz 기준값**이다

- [ ] **PID 게인 영속화** — **[나]** 튜닝 종료 후.
      `ros2 param set`은 재시작하면 사라진다. 저널에서 최종값 회수
      (`journalctl -u fish-robot | grep "게인 변경" | tail`) → 소스 초기화 목록 기본값에
      반영(진실원 한 곳) → 빌드 → 재시작 → 커밋

- [ ] **`speed_k` 확정** — 표시한 거리(예: 5 m)를 **자력 주행**하며 스톱워치.
      **예인으로 하면 안 된다.** 끌 때는 몸이 안 흔들려 정체압이 온전한데, 실제 유영은
      좌우로 흔들려 정체압이 `cos²β`만큼 깎인다. 예인 배율은 속도를 1~3 % 낮게 만든다

- [ ] **꼬리치기 피치 진폭 측정** ← `pressure_lag_ms` 작업의 선결 조건.
      지연 오차는 주기 운동에서 평균이 0이고 τ=1s 필터가 2 Hz를 12.6배 감쇠시키므로
      **정상 순항에서는 거의 문제가 안 된다** (진폭 3°: +0.6 %, 10°: +2.1 %).
      진폭을 재기 전에는 지연을 정밀하게 맞출 이유가 없다. CSV 의 `Hydro_Pitch`로 뽑는다

- [ ] **`pressure_lag_ms` 확정** — 위 진폭이 크게 나왔을 때만.
      제자리 꼬리치기 기록 → 오프라인에서 지연을 훑어 `corr(Q_dyn, sin θ)` 최소화.
      기본 72에서 출발. 정지 로그로는 검증 불가(ω ≳ 20 °/s 필요).
      ※ 기동 중(비주기)에는 평균이 0이 아니다 — 피치 20 °/s 지속 회전이면 v=0.6에서 +11.4 %

- [ ] **`roll`/`pitch` 오프셋 결정** — roll 은 3.87일 실측 +6.4°로 안정(장착 오프셋으로
      보임), pitch 는 놓는 방식에 좌우되어 상수가 없다. 중성부력 자세와 얽혀 있어
      물에 띄워봐야 정해진다. 정해지면 → **[나]** 목표 오프셋 파라미터

- [ ] **꼬리치기 pitch 편향 측정** — 주행 CSV 에서

## 5. 미뤄둔 것

당장 막지는 않지만 남아 있는 것들.

- [ ] **ch2(우현) 압력 센서 오프셋 계단 감시** — 8/26 거치(수직 고정) 후 +3.7 mbar 계단
      실측. 자세를 바꿔도 안 움직여 튜브 속 액체는 배제 — 패키지 응력에 의한 오프셋
      이동으로 판단. 재영점이 흡수해 지금은 무해. 원래도 잡음 최대(σ 0.24) 개체.
      **또 뛰면 센서 교체 검토.** 방어: 조립·거치 변경 후 btn1 3초.
      판별 시험 상세(수직/수평 대조로 액체 배제)는 `imu_detailed.md` §10.4.
      **미룬 이유**: 할 일이 아니라 감시 항목 — 재발해야 비로소 할 일(교체)이 생긴다

- [ ] **공기 중에서 속도가 음수로 나온다** (−0.6 m/s대) — `dP_hydro`가 물 밀도를 가정해
      공기 중에서 잘못 뺀다. 무해하지만 `FLAG_SPEED_OK`가 켜진 채라 헷갈린다.
      공기/물 판정(잠김 게이트 재활용)을 넣을 때 함께 처리.
      역으로 **공기 중 큰 음수 속도는 "물 밖"의 좋은 신호**이기도 하다.
      **미룬 이유**: 표시 문제일 뿐 제어에 무해하고, 어차피 공기/물 판정을 넣을 때
      한 번에 처리하는 게 두 번 일 안 하는 길

- [ ] **q 영점 게이트에 자이로 정지 판정** — 권고: 안 넣는다. 물속 q 영점이 버튼에서
      빠져 선택 사항이 됐고, 일정한 느린 표류는 어떤 센서로도 못 잡는다(진짜 방어는 절차).
      **미룬 이유**(사실상 폐기): 막으려는 오류를 실제로는 못 막는다 — 코드만 늘어난다

- [ ] **연직 속도** — 수심 미분. 샘플당 1.4 mm 잡음을 11 Hz로 미분하면 그대로는 못 쓴다
      (샘플 간 차분이 가짜 ±2 cm/s). 방법 확정(2026-08-26): **최근 1초 창 기울기 회귀**
      — 잡음 ±0.2 cm/s 수준, 지연 0.5초는 초 단위의 느린 연직 운동에서 무해.
      IMU 융합은 빠른 기동이 필요해질 때만 (아래 항목).
      **미룬 이유**: 소비자가 없다 — 수심 제어를 붙이는 날 20줄 넣으면 되고,
      미리 넣어도 검증할 물속 데이터가 없다

- [ ] **IMU 융합 속도** — 속도 + 가속도 바이어스 2상태 KF. 튜닝 근거가 물속 CSV에서 나온다.
      **미룬 이유**: 재료가 아직 없다 — 잡음·바이어스 튜닝이 물속 주행 CSV(3장 이후)에서
      나오고, 그 전에 창 회귀(위)로 충분한지 먼저 실측하는 게 순서

- [ ] **회전 레버암 유동 보정** — 요 60 °/s면 0.16 mbar. 원시 데이터로 크기 먼저 확인.
      **미룬 이유**: 오차 크기가 아직 가설 — 60 °/s는 극단값이라 실주행 CSV에서 실제
      회전 속도를 보고 무시 가능하면 안 한다. 보정부터 넣으면 검증 못 한 수식이 하나 늘 뿐

- [ ] **압력 11 → ~20 Hz** — 40 ms 대기가 데이터시트 18 ms 대비 2.2배 여유. 필요할 때만.
      **미룬 이유**: 지금 11 Hz로 부족한 게 없고, 올리면 검증된 타이밍 여유(2.2배)를
      깎는 데다 11 Hz를 가정한 곳(q LPF 계수 등) 점검이 따라붙는다. 얻는 것(연직 속도
      √2배, 수심 루프 위상, 피토 응답)은 전부 아직 안 하는 기능의 개선

- [ ] **AK8963 ASA ROM 미독** — |m|이 30 % 낮게 읽힌다. 크기만 영향, 헤딩 무관.
      고치면 재보정이 강제된다.
      **미룬 이유**: 고쳐서 좋아지는 값(|m| 크기)을 쓰는 데가 없고, 부작용(지자기 재보정
      강제)은 확실하다. 어차피 조립이 바뀌어 재보정할 때 같이 하는 게 공짜

## 다 끝나지 않는 것

- **지자기 보정은 조립이 바뀔 때마다 무효**다. 하우징을 닫으면 하드아이언이 통째로 바뀐다
  (실측: 조립 변경마다 지배 축이 옮겨 다녔다 — 최근 3회: Z → Y → Z)
- **로그 총량은 사람이 관리**한다. 시간당 99 MB. 안 쓸 때 `sudo systemctl stop fish-robot`.
  정리 시 `config/`는 절대 건드리지 말 것 (`git checkout -- config/`로 복구 가능)
- **서보 PWM 창(1325/1675)은 nRF 펌웨어 창(1250/1750) 안에 있어야** 한다 — 여기가 더
  좁은 건 안전, 넓히는 것만 nRF 와 함께. 이 저장소가 강제할 수 없다
- **조립·거치를 바꾸면 btn1 3초** — 압력 센서 오프셋이 응력으로 뛸 수 있다 (ch2 전력)
