# 물고기 로봇 IMU·자세추정 기술 정리 (상세판)

작성 2026-08-07. 수치는 실측이 원칙이며, 실측이 아닌 값은 "계산" 또는 "예측"으로
반드시 표기한다. 측정일과 방법을 함께 적는다.
철회된 주장(§7)도 "왜 틀렸는지"와 함께 남긴다 — 같은 함정을 두 번 밟지 않기 위해서다.

## 1. 시스템 구성

### 1.1 하드웨어 경로

```
nRF52840 (XIAO)                          Raspberry Pi 5 (Ubuntu Noble, ROS2 Jazzy)
┌─────────────────┐   UART 46B 100Hz   ┌──────────────────────────────────┐
│ 자체 IMU (6축)   │ ─────────────────▶ │ uart_bridge_node                 │
│ BLE 조종기 수신  │                    │   → /raw/imu_6dof (100Hz)        │
│ 서보/ESC PWM 출력│ ◀───────────────── │   → /rc/command, /rc/status      │
└─────────────────┘   UART 10B 100Hz   │                                  │
                                        │ i2c_driver_node                  │
I2C (/dev/i2c-1)                        │   → /raw/magnetometer (~94Hz)    │
  AK8963 지자기 (0x0C,                  │   → /sensor/pressure_raw (~11Hz) │
    MPU9250 0x68 바이패스 경유)          │                                  │
  MS5837 압력 ×3 (0x76,                 │ state_estimation_node (Mahony)   │
    TCA9548A 먹스 뒤)                   │   → /filtered/attitude (100Hz)   │
                                        │ state_estimation_ekf_node (EKF)  │
                                        │   → /filtered/attitude_ekf       │
                                        │   → /filtered/ekf_status         │
                                        └──────────────────────────────────┘
```

- 가속도·자이로는 **nRF52840 보드의 자체 IMU**에서 온다. MPU9250의 6축(MPU6500)은
  깨우지도 읽지도 않는다 — MPU9250은 AK8963에 도달하기 위한 I2C 바이패스일 뿐이다.
- 지자기는 ~94 Hz로 살아 있고(2026-07-31 확인), 시스템은 **9축**으로 돈다.
- **2026-08-17부터 `state_estimation_ekf_node`가 `/filtered/attitude`의 단독
  발행자로 제어 경로를 인수했고, `state_estimation_node`(Mahony)는 launch에서
  빠졌다(§9).** 위 다이어그램의 발행 구도는 그 이전 기준이다.

### 1.2 단위 — REP-103이 아니다

| 항목 | 실제 단위 | 비고 |
|---|---|---|
| 가속도 | **g** | 정지 시 \|a\| ≈ 1.03 (9.81 아님) |
| 각속도 | **도/초** | 필터가 rad 변환 (`M_PI/180`) |

`sensor_msgs/Imu` 타입이지만 변환 없이 발행된다. Mahony는 가속도를 정규화해서
쓰므로 스케일은 무관하고 방향만 중요하다. **새 소비자는 스스로 변환해야 한다.**

### 1.3 타이밍

- 전 시스템 100 Hz (10 ms) 루프. 실측 발행률은 92~94 Hz.
- IMU 스트림에 구멍이 간헐적으로 생긴다 — 2026-08-07 세션 수 시간 관측에서
  **60~130 ms 구멍 ~20회**, 과거 기록에는 **~0.5 s** 구멍도 있다.
  Mahony는 dt를 `[0.001, 0.1] s`로 클램프해 흡수하고, EKF는 실측 dt를 그대로
  적분한다 (공분산이 신뢰도를 자동 조정하므로 상한 클램프가 없는 쪽이 옳다).
- 타임스탬프는 nRF의 샘플 시각이 아니라 **Pi 도착 시각** (`uart_bridge`가 찍음).

## 2. 좌표계와 축 변환 — 전 축 검증 완료

### 2.1 규약

- 몸체 좌표계 FLU (앞-왼쪽-위), 칩 → 몸체 변환:
  `R = [0 0 −1; −1 0 0; 0 1 0]` (det = +1), 즉 `FLU = (−z, −x, +y)`
  (`state_estimation_node.cpp:575-580`).
- **pitch 양수 = 코가 아래** (항공 규약과 반대. 2026-08-04 실측 확정).
- 반시계 회전 = yaw 양수 = 좌선회.
- 장착 기준선이 수평이 아니다: **pitch ≈ 7.9°**. roll/pitch에는 `yaw_offset_`
  같은 영점 보정이 없어 비수평 장착이 그대로 상수 오프셋으로 보인다.

### 2.2 가속도 축 검증 (2026-08-04, 틸트 교차축 시험)

기울임 시험 두 번: 물리 회전축이 비수평 기준선으로 예측한 위치에서 **0.01°**
이내. 코 들면 pitch 음수, 좌현 들면 roll 양수 — 부호까지 일치.

주의: 기울어진 기준선에서 월드 수평축 둘레로 45° 돌리면 오일러 *다른* 각이
~2° 움직인다. 기하학적 결과이지 축 오류가 아니다.

### 2.3 자이로 축 검증 (2026-08-06, 쿼터니언 적분)

자이로만 쿼터니언으로 적분해 예측한 중력 방향을 (이미 검증된) 가속도와 비교.

| 시험 | 결과 |
|---|---|
| 61초 임의 회전 후 정지 잔차 | 최악 1.79° |
| 평평한 360° 회전 | **+359.96°** (부호·크기 일치) |
| 그때 기울기 잔차 | 0.53° (Z가 X/Y로 새지 않음) |
| 옆으로 눕히기 (90°) | 87.1° |
| 꼬리로 세우기 (90°) | 94.8° (수평 재배치 반복성 3.3°) |

판정 규칙: **정지 시 잔차로만 판정한다.** 움직이는 중에는 가속도가 비력
(중력−선형가속도)이라 오차가 7.7°까지 뛰지만 정지하면 1° 미만으로 복귀한다.
또 pitch ±90° 부근에서 오일러각은 퇴화한다 — 실제 자세가 0.9° 움직이는 동안
roll 표시가 20° 배회했다. **정지 판정은 중력 벡터로, 절대 오일러각으로 하지 말 것.**

축 변환이 틀렸다면: 회전은 각도를 보존하므로 **스윕 각도가 줄어드는 일은 구조적으로
불가능**하다. 스윕이 짧게 읽히면 센서가 몸체와 같이 안 돌았거나(장착) 가한 각도를
잘못 잰 것이다. 45°를 29°로 줄일 수 있는 배율 오류라면 90°는 58°로 읽었어야 한다 —
위 표의 87.1°/94.8°가 배율 오류를 배제한다. 손대중 각도는 ±15° 오차가 있다 —
숫자를 믿을 것.

## 3. 자이로 바이어스

### 3.1 부팅 캘리브레이션

`state_estimation_node`는 부팅 시 1000샘플(~10초) 평균으로 바이어스를 잡는다.
이 동안 **아무것도 발행하지 않으므로** 모터 출력도 없다. 로봇이 완전히 정지해
있어야 하며, 이때 움직이면 바이어스가 세션 내내 오염된다.

### 3.2 세션 간 불안정 — 실측

| 측정 시점 | z축 바이어스 |
|---|---|
| 자이로 축 시험 세션 | −0.044 °/s |
| 몇 시간 뒤 비교 세션 | **−2.21 °/s** (50배) |

−2.2 °/s = **30초에 66°의 유령 회전**. 결과 두 가지:

1. **어떤 6축 yaw 드리프트 수치도 그 세션에서만 유효하다.** 스펙으로 이월 금지.
2. 자이로를 정답 기준으로 쓰는 모든 시험은 **시작 6초 정지 구간에서 바이어스를
   먼저 빼야 한다** (`verify_spin.py`, `exp_b.py`가 그렇게 구현됨).

EKF는 바이어스를 상태에 넣어 온라인 추정하며, 10분 정지 시험에서 원시 자이로
평균과 **3축 모두 0.002 °/s 이내**로 일치했다
(추정 `[+0.6612 +0.2523 −2.2106]` vs 실측 `[+0.6615 +0.2534 −2.2083]`).
Mahony의 `Ki=0.005` 적분도 따라가긴 하나 계산상 시정수 ~400초로 느리다(미실측).

### 3.3 잡음 설정

`gyro_noise_sigma` 설정 0.05 °/s/√Hz, 정지 실측 0.0028~0.0069. 약 10배 여유는
진동·도착시각 지터 대비 의도된 것이다. **2026-08-17 Allan 분산으로 검증 완료**
(2시간, 711,328샘플, 98.8 Hz, overlapping):

| 축 | ARW [도/초/√Hz] | 바이어스 불안정성 [도/초] | 그 τ [초] |
|---|---|---|---|
| x | 0.0065 | 0.0024 | 434 |
| y | 0.0060 | 0.0011 | 69 |
| z | 0.0078 | 0.0018 | 117 |

설정 0.05는 실측 ARW의 **6.4~8.3배** — 이제 짐작이 아니라 측정된 여유분이다.
`bias_tau` 1000 s는 불안정성 최소점(69~434 s)과 같은 자릿수로 타당하고,
`gyro_bias_rw_sigma` 0.002는 실측 불안정성(0.0011~0.0024)과 일치한다.
**파라미터 변경 불요.** 덤: 기록 중 z 바이어스가 2시간에 걸쳐 −3.18 → −3.12로
느리게 흘렀다(온도 추정) — 온라인 바이어스 추정이 필요한 이유의 직접 증거.

## 4. 지자기 — 보정 확정, 그리고 한계까지 확인

### 4.1 하드웨어와 소프트웨어 결함 하나

- AK8963, MPU9250(0x68) 바이패스로 0x0C 접근. ~94 Hz.
- 변환은 축마다 고정 `0.15 µT/LSB`. **ASA 감도 ROM(0x10–0x12)을 읽는 코드가
  없다** (`i2c_driver_node.cpp:203-205`). 이 때문에 보정 후 |m| = 34.7 µT로
  한국 실제(~50 µT)보다 **30% 낮다.** 방향은 옳으므로(스핀 비율 1.01) 헤딩·자세
  무영향 — **크기 전용 결함.** 고치면 소프트아이언 배율이 ASA 차이를 흡수하고
  있으므로 보정도 다시 해야 한다.
- 500 ms 무응답 시 9축 → 6축 자동 폴백 (Mahony·EKF 동일 타임아웃).

### 4.2 축 재배치 — 확정, 재론 금지

`(mx, my, mz)칩 → (my, mx, −mz)몸체` (`state_estimation_node.cpp:495-521`).
**보정 먼저, 재배치 나중** — 계수가 칩 축 기준이므로 순서가 규약이다.

검증: 1164점 텀블(8분면 전부)로 타원체를 맞춘 뒤 **복각 144.3° ± 3.2°**
(한국 정답 143°; 전 표본 채점 기준 — 정지 표본만 쓰면 144.5 ± 2.9°이며 이하
표들은 정지 표본 기준이다). 복각은 자기장-중력 사이 각이라 하드아이언과 세 축이
모두 맞아야만 정답이 나온다 — 한 측정으로 두 질문이 동시에 닫혔다. 후보 24개
재배치 중 이것만 복각이 일정했고 2위는 110.6° ± 23.9°(흔들림 8배)였다.
칩 축은 조립·이동으로 변하지 않으므로 **이 결과는 영구적**이다.

(코드 주석의 유도 근거 — MPU9250 데이터시트의 다이 정렬 — 는 전제가 틀렸다.
가속도는 MPU6500이 아니라 nRF 자체 IMU에서 온다. 답은 맞고 이유가 틀린 경우.)

### 4.3 하드아이언의 크기와 min/max의 실패

2026-08-06 텀블 산출 파일 (`log_csv/mag_calib_params.txt`; IMU 단독 상태에서 측정 —
2026-08-17 조립 상태 재보정으로 대체됨, §9. 직전 파일은 `.bak_20260806_194340`으로 백업):

```
하드아이언  -12.2555  23.5024  -89.7587   [µT, 칩 축]     총 93.6 µT
소프트아이언   1.046   0.983502  0.973518  [배율]
```

**하드아이언 93.6 µT는 실제 지구 자기장(~50 µT)의 두 배 — 이 센서가 읽는
|m|(34.7 µT, §4.1) 기준으로는 세 배 — 가까이 되고, 그중 −89.8이 칩 Z축**이다.
수평 회전은 수평 성분만 보므로(현 피팅 벡터 기준 26.5 µT; 옛 기록의 37.8 µT는
당시 평면 스핀이 본 수평 오프셋으로 전체의 일부였다) **평평한 스핀으로는
구조적으로 찾을 수 없다.** 같은 날 같은 구성에서 네 보정을 나란히 채점:

| 보정 | \|m\| | 흩어짐 | 복각 (143° 정답) |
|---|---|---|---|
| 무보정 | 94.4 ± 20.9 | 22.1 % | 94.7 ± 51.0° |
| 이전 세션 파일 | 90.7 ± 19.2 | 21.1 % | 101.9 ± 39.3° |
| **btn2 min/max (당일 실측)** | 45.9 ± 17.5 | **38.1 %** | 124.7 ± 24.1° |
| **텀블 + 타원체 피팅** | 34.7 ± 1.5 | **4.3 %** | **144.5 ± 2.9°** |

**min/max는 무보정보다 나빴다** (38.1 % vs 22.1 %; 표 3행은 2026-08-06 18:29에
같은 구성에서 btn2로 실측한 것이다). 극값 두 점만 쓰므로 손 텀블이
진짜 극값을 놓치면 중심이 틀어지고, 그 결과 나온 소프트아이언 배율
(0.953/0.953/1.108)이 그나마 자기일관적이던 장을 더 망가뜨린다.
**btn2 길게 누르기와 `/calibrate_mag` 서비스는 둘 다 이 min/max
경로로 같은 파일을 조용히 덮어쓴다** — 백업도 품질 검사도 없으므로 어느 쪽도
쓰지 말고 `magneto_cal.py`(타원체, 품질 게이트·백업 내장)를 쓸 것.
(**2026-08-17 폐기 완료**: 두 트리거 모두 `magneto_cal.py`를 실행하도록 바뀌었고,
min/max 코드는 은퇴한 `state_estimation_node` 안에만 남아 있다 — §9.)

피팅 함정: 데이터를 **중심 이동 후** 이차곡면을 풀 것. 데이터 구름의 평균이
원점에서 ~65 µT 떨어져 있어(피팅 *중심* 93.6과는 다른 양 — 반구 커버리지가
기울면 평균과 중심이 다르다) 그대로 풀면 제곱항이 준평행이 되어 반지름이 음수로
나온다.

### 4.4 보정 모델은 한계에 도달했다 — 더 맞추려 하지 말 것

기운 축을 허용하는 일반 타원체(9파라미터)로 같은 텀블을 재피팅:

| | \|m\| | 흩어짐 | 복각 |
|---|---|---|---|
| 현재 파일 (축정렬, 6파) | 34.74 ± 1.49 | 4.28 % | 144.47 ± 2.86° |
| 일반 타원체 (9파) | 34.74 ± 1.43 | 4.12 % | 144.34 ± 2.79° |

중심 차이 **0.25 µT** (헤딩 사인 0.44° 예측 — 실측 3.67°[08-07 실험 B 잔차,
§4.6 각주 참조]의 1/8), 비대각
**1.5 %**. 이 로봇의 왜곡은 실제로 축정렬 타원체이며 **더 뺄 하드/소프트아이언이
없다.** 잔차의 방향-일관성은 ~50 % (15° 이내 이웃쌍 상관 +0.48, 이웃차 RMS
1.64 µT vs 순수 잡음 예측 2.13 µT — 몸 고정 항이 아니라 위치 항과 부합)라 완벽한
고차 모델도 3.67° → ~3.0°가 한계다.

### 4.5 끝단 헤딩 검증 — 합격 (2026-08-06, 360° 스핀)

66초 손 회전, 정답 = 중력축 둘레 자이로 적분(그 축 자체가 +359.96°로 검증됨).

| | 스윕 | 비율 | 역행 (0.5s 평활) |
|---|---|---|---|
| 물리 (자이로) | −357.74° | — | — |
| **보정 지자기** | **−361.79°** | **1.01** | 7.7° |
| 무보정 지자기 | −1.55° | 0.00 | 102.0° |
| Mahony yaw | −359.54° | 1.01 | 0.0° |

- **총량이 아니라 45° 구간별로 판정한다.** 보정 지자기는 전 구간 38~52°로 모두
  45° 근방. 무보정은 구간마다 12~19°씩 느리다가
  270–315°에서 **−45.1° 역주행**했다 — 옛 헤딩을 못 쓰게 만든 건 이 역주행이다.
- **역행은 0.5초 평활 후 계산.** 100 Hz·33 °/s에서 참 스텝은 0.33°/샘플로 지자기
  잡음보다 작아, 원시 채점은 좋은 데이터도 3500°가 넘게 나온다.
- 잔차: 중앙값 2.22°, 95%ile 5.87°, σ 3.10° — 그리고 한 바퀴 한 주기 사인파
  3.58°이며, 그 한 주기를 빼면 2.08°가 남는다. 단독 18.1° 이탈은 −3 °/s 순간의
  스파이크다 (6601 샘플 중 10° 초과는 10개뿐). 08-07 실험 B의 깨끗한 −346° 한
  바퀴에서 독립 재현: 3.67°, 2주기 항은 0.66°, 3주기 항은 0.18° — 정말로 1주기다.
- 회전 중 |m| 흩어짐은 **2.5 %** — 텀블의 4.3 %보다 좋다. 수평 스핀이 쉬운
  경우이긴 하나, 자세가 변해도 보정이 무너지지 않음을 확인해 준다.

| 08-07 12:10 | 반시계 −346.3° | 3.60° | 125.6° ± 0.3 |

### 4.7 기타 실측

- **Pi는 오염원이 아니다** (2026-08-06 실측): 정지 40 s → 4코어 100 % 부하 40 s →
  정지 40 s, 로봇은 0.07° 이내 정지, 부하는 확인됨(1647→2400 MHz, 65.3→75.9 °C).
  장은 2.15 µT만 이동(수평 성분 1.05 µT ≈ 헤딩 2.7° — 전체 오염의 ~5 %).
  오프셋이 사실상 상수라서 보정이 성립한다.
- **열 드리프트 미해결**: 부하 *후* 3 µT 이동 + 잡음 약 3.9배(σ 0.68→2.64).
  3 µT ≈ 헤딩 8° — 달성 가능 정확도의 상한일 수 있다.
- **보정은 장소가 아니라 조립에 묶인다.** 하드/소프트아이언은 몸 고정이라 수영장
  까지 그대로 가고, 환경 자기장은 피팅 중심을 옮기지 못한다(반지름만 변화).
  옛 파일은 **IMU 단독 상태**에서 잰 것이라 최종 조립 후 재보정이 필수였고,
  **2026-08-17에 완료됐다 — 하드아이언이 조립으로 완전히 바뀌었다 (§9).**
  재보정 절차 함정: **한 자리에서 텀블할 것 (강철 가구에서 ≥1 m).** 들고
  이동하며 텀블하면 변하는 외부 자기장을 통과해 피팅이 오염된다.
- 파일은 노드 시작 시 1회 로드 — 손으로 수정하면 재시작 필요. (2026-08-17부터
  `magneto_cal.py` 저장 성공 시 EKF 노드가 자동 리로드한다, §9.)

### 5.1 Mahony (state_estimation_node) — 제어에 사용했음 (2026-08-17 은퇴, §9)

- 9축 상보필터, `Kp=2.0`(τ≈1 s), `Ki=0.005`(바이어스 추종 τ≈400 s, 계산값).
- 오차 벡터 = 중력 외적 + **자기장 외적을 같은 벡터에 합산** → 자기장 오차가
  roll/pitch로 들어갈 수 있는 구조. 옛 나쁜 보정으로 2026-07-31 정지 실측:
  중력 기준 roll −1.19 / pitch 3.75 vs Mahony roll −6.16 / pitch 2.10 —
  **5.0°/1.7° 오염**이 제어 루프로 들어갔다.
- 모드 밀수: AUTO일 때 roll에 +5000을 더해 발행 (해독은 `|x|>2500`으로 부호
  양쪽을 처리). 소비자 3개가 독립적으로 해독 — 인코딩을 바꾸면 네 파일을 다 바꿔야 한다.
- `eInt_`에 안티와인드업 없음 (Ki가 작아 현재는 무해).

**halfwy 버그 (2026-08-06 수정, `state_estimation_node.cpp:199`)**:
예측 자기장 y성분의 `bz` 계수가 `0.5−q1q1−q3q3`(R22)로 잘못 적혀 있었다.
정답은 `q0q1+q2q3`(R21). 항등 자세에서 예측 y가 0이어야 하는데 0.5·bz가 나왔다.
**증상이 보정 품질에 비례해 커졌다** — 복각이 ~100°로 틀렸을 땐 bz가 작아 5.0°,
텀블로 복각을 144°에 맞추자 bz가 5배 커져 **14.0°**. "재보정했더니 자세가
나빠졌다"를 "보정이 나쁘다"로 읽으면 안 되는 이유.

`btn1_long_processed_`가 생성자 초기화 목록에 빠져 있었다 (첫 `/rc/status`의
`btn1 == 0`이 지울 때까지 비결정값) — **2026-07-31 수정.**

되고 읽히지 않는다 — 옛 버튼 구현의 잔재.

### 5.2 EKF (state_estimation_ekf_node) — 관측자로 병렬 주행 (2026-08-17 제어권 인수, §9)

MEKF: 공칭 쿼터니언 + 6차 오차상태 `[δθ; δb]`, double, Eigen, Joseph 형태.

핵심 설계 세 가지, 전부 실측으로 정당화됨:

1. **지자기 갱신은 수평 yaw 1차원** (`H_m = [ĝ_bᵀ 0]`). 구조적으로 roll/pitch를
   못 건드린다. 실측(§6.4): 지자기 복구 사건에서 roll 요동 — 13초 변동폭 기준
   Mahony 2.69° vs EKF 0.05°, 복구 순간 계단 기준 −0.74° vs +0.01°.
2. **가속도 게이트의 관측불가 방향 사영**: 게인 `K`에서 월드 수직(`g_b`) 방향을
   사영 제거. `H_a`의 영공간이 이론상 `g_b`여도 `K = P Hᵀ S⁻¹`가 P의 yaw↔기울기
   상관(60° 초기 yaw 분산이 증폭)을 타고 yaw를 다시 끌어들인다 — 흔들기
   1회당 **−33°/−37°** 실측 (같은 사건에서 외적 보정이 구조상 yaw-무관인 Mahony는
   0.7°/2.7°), 수정 후 −0.8°/−0.2°. `dx`만 사영하면 P가 yaw 정보를
   계속 세므로 원인은 남고 증상만 숨는다. **게인을 사영할 것.**
   진단: 6축에서 yaw 1σ는 커지기만 해야 한다 (수정 전 40°→7°, 수정 후 60°→61°).
   단 샘플 단위로 판정하지 말 것 —
   부동소수점 잡음으로 5027회 갱신 중 66회 감소(누적 −0.025° vs 증가 +5.531°,
   0.44 %; 최대 한 걸음 −0.011° = σ의 0.018 %, 연속 2회 초과 없음; σ 자체는
   59.32° → 64.82°로 성장)는 Joseph 형태·대칭화의 부동소수점 잡음이라 정상.
   진짜 누설(수정 전)은 40°→7°로 *지속* 감소했다.
3. **적응형 R**: `|‖a‖/a_ref − 1|` 기반. 소프트 무릎 0.02 g(연속 팽창), 하드
   컷 0.30 g. 기준 `a_ref`는 부팅 실측(≈0.99~1.03 g).

주의: 복각 기준도 부팅 실측인데 세션마다 135.8~140.9°로 잡혀 기대 143°에서
최대 7.2° 어긋난 적 있다(게이트 ±15°의 절반). 부팅 시 정지·이격 필수.

발행: `/filtered/attitude_ekf`, `/filtered/ekf_status`(바이어스·1σ·게이트 플래그).
**`/filtered/attitude` 발행자는 반드시 하나** — 둘이 되면 PID 루프가
200 Hz가 되어 dt 생략 게인이 전부 틀어진다. 관측자 시절에는 이 노드가 절대
발행하지 않는 쪽이었고 서비스도 없었다(`std_srvs` 미링크로 컴파일 타임 강제);
launch 8번째 노드로 편입(2026-08-07), `respawn=False`. **2026-08-17부터는 반대로
이 노드가 단독 발행자이고 `/calibrate_mag` 서비스도 소유한다 (§9).**

```
바이어스 추정 vs 원시 평균: 3축 모두 0.002 °/s 이내 (z = −2.21 °/s를 흡수)
```

### 6.4 지자기 상실 → 복구 (2026-08-07, SIGSTOP 주입)

`i2c_driver_node`를 SIGSTOP으로 8초 얼림(respawn 회피, 복구 시점 제어).
폴백은 정확히 **508 ms**(설정 500), NaN 0개.

| 전환 계단 [°] | Mahony r/p/y | EKF r/p/y |
|---|---|---|
| 상실 순간 | −0.07 / −0.06 / +0.29 | +0.00 / −0.00 / +0.09 |
| **복구 순간** | **−0.74 / −0.48 / +0.80** | +0.01 / +0.00 / +0.53 |
| 복구 후 13초 변동폭 | roll 2.69 / pitch 1.72 | **roll 0.05 / pitch 0.04** |

Mahony는 지자기 사건 하나에 roll이 2.7° 요동하고 그게 PID로 들어간다. EKF는
구조상 불가능(§5.2-1). 한계: 30초 기록이라 완전 정착 시간은 미측정, 상실 중
EKF yaw가 6.5초에 1.15° 움직인 것(전환 과도로 추정)은 미확정.

## 7. 방법론 교훈 — 실제로 밟은 함정들

### 7.1 유령 발행자 (가장 비쌌던 함정)

"9축 Mahony가 구조적으로 ~6.8°를 기울기에 넣는다"는 결론은 **철회됐다.**
측정 당시 `/filtered/attitude`에 발행자가 둘이었다 — 재빌드 후에도 살아남은
고아 프로세스(ppid 1, **삭제된 바이너리** 실행)가 새 노드와 번갈아 발행해 두
필터 출력이 섞였다. 깨끗한 토픽 재측정: 0.134°.

- `ros2 node list`는 이름 중복만 보여주고, `pgrep -x`는 못 찾는다(comm 15자
  절단). **`/proc/*/exe`에서 `(deleted)`를 찾을 것.**
- 비교 실행 전 필수: `ros2 topic info /filtered/attitude --verbose | grep -c
  "Endpoint type: PUBLISHER"` == **1**.
- 오염된 6.8°는 여섯 개 30초 창에서 6.7~7.0°로 **안정적이었다.** 오염원이 정지해
  있으면 재현성은 타당성의 증거가 아니다.
- 후속 결론: 그 6.8°를 고치려고 제안됐던 수정(Mahony 자기 오차를 `halfv`에 사영)
  은 **해결할 실증된 문제가 없으므로 적용 금지.** §5.1의 구조적 약점(자기장 오차가
  같은 보정 벡터에 합산)은 실재하지만, halfwy 수정 + 좋은 보정 상태에서는 측정
  가능한 비용이 없다. 이론만 근거로 재시도하지 말 것.

### 7.2 순환논증 (두 번째로 비쌌던 함정)

사인파 3.58°를 "잔여 하드아이언 1.34 µT, 피팅 잔차 1.5 µT와 일치"로 설명했다.
그러나 1.34는 **사인파에서 역산한 값**이라 일치는 순환이고, 1.5 µT는 중심
오차가 아니라 **흩어짐**이다(보정으로 제거 가능한 건 중심 오차뿐). 재피팅으로
반증했고(§4.4), 위상 분석으로 진짜 원인(환경)을 찾았다(§4.6). 이 잘못된 설명은
사람을 재보정으로 보낸다 — 그래서 철회 기록을 남긴다.

### 7.3 미결정 피팅 (세 번째 철회)

가속도계에 "~2 % 비대칭, ≤0.6° 오차"가 있다는 옛 주장은 **3개 자세에 6개
파라미터를 피팅한 미결정(underdetermined) 문제의 아티팩트**였다 — 자세 산포가
센서 오차로 보고된 것. 텀블의 정지 552점(1164점 중; 자세가 충분히 다양)으로 다시
풀자 바이어스 `(−0.0043, +0.0010, −0.0028) g`, 축 반지름 0.3 % 일치, 보정 적용
효과는 중력 방향 평균 0.26° / 최대 0.37°뿐이고 흩어짐도 1.11 % → 1.07 %로 거의
안 움직였다. ≤0.4 %의 배율 오차는 EKF의 `a_ref_` 게이트도 의미 있게 움직이지
못한다 — 구현할 것 없음.
**파라미터 수보다 유효 관측이 적으면 피팅은 뭐든 "찾아낸다."**

### 7.4 채점 규칙 모음

| 규칙 | 이유 |
|---|---|
| 자이로를 정답으로 쓰기 전에 바이어스부터 뺀다 | −2.2 °/s = 30초에 66° |
| 헤딩은 총량이 아니라 45° 구간별로 | 옛 실패는 총량이 아니라 역주행 |
| 역행은 0.5 s 평활 후 | 원시 채점은 좋은 데이터도 >3500° |
| 축 시험은 정지 잔차로만 | 운동 중 가속도는 비력 (7.7° → 정지 시 <1°) |
| 정지 판정은 중력 벡터로 | 오일러는 pitch ±90에서 퇴화 (0.9° 실제 → 20° 표시) |
| 정지 비교로 필터 우열 가리지 않기 | 정지에선 구분 불가 (§6.1) |
| 손 스핀 헤딩 검증 바닥 ~3° | 환경 기울기 (§4.6) |
| yaw 1σ 진단은 누적으로 | 샘플 단위는 부동소수점 잡음에 오탐 |

계속 돈다. 로그 정리 전에 이 세 파일을 먼저 확인할 것.

### 10.3 압력 서브시스템 첫 실전 측정 (벤치, 공기 중)

`hydro_estimator_node`가 systemd 아래에서 처음 돌았다. 발행자 1개, 노드 8개,
포트 지문 3채널 전부 "확인", CSV 47열, `/filtered/hydro` 9.3 Hz.

| 값 | 실측 | 판정 |
|---|---|---|
| `depth` | **−0.0003 m, σ 1.0 mm** | 정지 벤치. 채널 σ 0.13 mbar 를 두 개 평균한 값과 일치 |
| `static_gauge` | −0.027 mbar (σ 0.10) | |
| `q_raw` | +0.711 mbar (σ 0.126) | 예측 σ_q 0.189 보다 오히려 낮다 |
| 공기 Δb | **0.7600 mbar** (산포 0.725) | 이전 실측 0.775 와 0.015 차이 — 개체차가 재현된다 |
| `flags` | `0x01F` | 다섯 개 전부 정상 |

대기압 영점 ch0/1/2 = 1005.95 / 1006.45 / 1004.00 mbar (산포 0.46/0.42/0.84).

**`speed` 가 −0.62 m/s 로 나온다** — 알려진 공기 중 인공물이다.
`q = q_raw − dP_hydro − q_offset = 0.711 − 1.844 − 0.760 = −1.893 mbar`.
