## 1. 켜기 전

1. **로봇을 고정한다.** 전원이 들어오면 서보가 움직일 수 있다.
2. **흔들리지 않는 곳에 둔다.** 기동 후 약 10초간 자이로 영점을 재므로 그동안 움직이면 안 된다.
3. **물이 없어야 한다.** 대기압 영점을 공기 중에서 잡는다. 물속에서 잡히면 잠긴 상태가
   "수면"이 되어 수심이 통째로 틀어진다.
4. 조종기를 켤 거라면 **로봇보다 먼저** 켠다.

## 2. 전원 투입 타임라인

`t`는 **서비스가 시작된 시각** 기준이다. 전원 인가부터 서비스 시작까지는 OS 부팅 시간이
따로 걸린다.

| 시각 | 일어나는 일 | 사람이 할 일 |
|---|---|---|
| t + 0초 | systemd가 `fish-robot.service` 시작 | — |
| **t + 45초** | ROS2 launch가 뜨고 노드 8개 프로세스 시작 | — |
| t + 47초 | 각 노드 초기화, 압력 PROM 로드, EKF 배너 | — |
| t + 47초 | **EKF 초기화 완료 (50샘플) → 자세 발행 시작** | — |
| t + 47초 | 복각(dip) 1회 검사 ← **여기서 오류가 나는지 볼 것** | 3장 확인 |
| t + 47~57초 | **자이로 영점 정지 창 (1000샘플)** | **가만히 둘 것** |
| t + 57초 | 정지 창 완료 → 자이로 바이어스 확정 | — |
| t + 47초 | `[Hydro] 대기압 영점 웜업 대기 (0 / 180초)` ← **첫 줄은 곧바로 뜬다** | — |
| t + 77초부터 | 30초마다 웜업 진행 로그 (30/60/90/120/150) | — |
| t + 225초 | 대기압 영점 수집 시작 (101샘플) | **9초간 건드리지 말 것** |
| **t + 234초** | 영점 완료 → **수심 유효** | 물에 넣어도 됨 |

**전원 인가부터 수심이 나오기까지 대략 4분**이다.

### 자이로 정지 창이 실패하면

로봇이 흔들리면 창을 다시 시작한다. 최대 3회:

```
[WARN] [EKF] 정지 판정 실패 (자이로 std=0.80도/초, |a| 변동=0.223 g) -> 창 재시작 (1/3)
```

판정 기준은 자이로 표준편차 **1.0도/초 미만**, 중력 크기 변동 **0.05 g 미만**(창 전체의
최대편차이므로 순간 튐 한 번이면 창 전체가 실패한다)이다. 한 번 실패할 때마다 10초가 더 걸린다.

**4번째에도 실패하면 포기하지 않는다.** 불확실성을 10배(0.05 → 0.5도/초)로 부풀려 **수용**하고
ERROR를 남긴다 — 즉 바이어스는 어떻게든 주입된다. 최대 약 40초.
```
[ERROR] [EKF] 정지 판정 3회 실패 -> 불확실성 10배로 수용 (바이어스 초기값 신뢰 낮음)
```

**정지 창은 자이로 바이어스만 잡는 게 아니다.** 마감할 때 세 가지를 동시에 확정한다:
자이로 바이어스, 중력 크기 기준 `a_ref_`, 그리고 **지자기 크기 게이트의 기준 `|m|`**.
`|m|` 기준은 로봇이 놓여 있던 **한 자세에서 한 번만** 잡히고 재보정 전까지 갱신되지 않는다.
그래서 이 10초 동안 로봇을 움직이면 세 가지가 한꺼번에 오염된다.

**중요**: 이 10초 동안 자세 발행이 멈추지는 **않는다.** EKF는 50샘플(0.5초)에 이미 발행을
시작했고, 정지 창은 **병렬로** 돌다가 끝나면 유사관측으로 합류한다. (예전 Mahony 노드는
10초간 침묵했지만 지금은 아니다.)

다만 **첫 0.5초 동안은** 자세가 아직 안 나온다. 그동안 발행되는 것은 `/CH_IMU`, `/CH_MEGNET`
둘뿐이고, `pid_control_node` 는 콜백이 없어 **모터 출력도 없다**. 초기화는 지자기 샘플이
1개 올 때까지 기다리되 최대 1초(100샘플)까지만 기다리고 6축으로 진행한다.

### ❌ 이것이 보이면 멈추고 조치할 것

**복각 오류 — 방위를 믿을 수 없다는 뜻**
```
[ERROR] [EKF] 복각이 물리적으로 불가능합니다: 실측 24.0도, 기대 143.0도
[ERROR] [EKF]   이 상태에서 yaw는 신뢰할 수 없습니다. use_mag:=false 권장.
```
지자기 보정이 잘못됐거나 없다는 뜻이다. **6장의 지자기 보정을 하라.**

> #### 이 한 줄이 방위 신뢰성의 **유일한** 판정이다
>
> **오류가 떠 있어도 `EKF_Flags`는 정상값 `7`을 유지하고, 지자기는 100 % 융합된다.**
> 런타임 복각 게이트는 지구 상수가 아니라 **첫 샘플로 부트스트랩한 기준**과만 대조하므로
> (`:975` → `:1003`), 계통적으로 틀린 값은 자기 일관적이어서 영영 못 잡는다. 143°와의 절대
> 대조는 부트스트랩 시점 **딱 한 번** 일어나고, 어긋나도 **ERROR 6줄만 찍고 그대로 진행한다**
> — 조기 return도, `use_mag` 강등도, 플래그 비트도 없다 (`:977-998`).
>
> **현재 상태의 실제 크기** (2026-08-21 실측):
>
> | | 값 |
> |---|---|
> | 복각 오차 | **119.1°** (실측 23.93° vs 지구값 143°) — 런타임 게이트 ±15°의 **8배** |
> | 보정 후 \|m\| | 103.73 µT. 이 AK8963은 지구 자기장을 ~34.7 µT로 읽으므로 **잔여 하드아이언이 지구 자기장의 약 3배** |
> | yaw로 들어가는 수평 성분 | 측정 42.0 µT 중 지구 성분은 20.9 µT — **신호:오염 ≈ 1:1** |
> | 노출량 | 421,018행 / 약 70분 전 구간에서 **기각 0건, 6축 폴백 0건** |
> | roll/pitch 영향 | **0** (구조적 면역, §5.2) |
>
> 결과적으로 yaw가 수렴하는 곳은 "북"이 아니라 **하드아이언 벡터의 방위각**이다. 하드아이언
> 수평분이 지구 수평분보다 크므로 **절대 방위 오차는 원리적으로 ±180° 전 범위** — 절대 방위
> 기준이 사실상 없다.
>
> **왜 겉보기엔 멀쩡한가**: 오프셋이 기체에 고정돼 있어 **lock 자체는 안정적**이다. 그래서
> 수동 조종의 헤딩 유지는 정상으로 보이고, btn2 헤딩 영점이 오차를 덮어버린다.
> **조용히 틀어지는 것은 AUTO의 절대 방위 명령뿐이다.**

**압력 채널 사망**
```
[WARN] [MS5837] 채널 N 압력센서 응답 없음 (Reset 실패).
[ERROR] [I2C Driver] ... I2C 버스 잠김 의심 ...
```

**포트 배정이 바뀜**
```
[ERROR] [포트] left(ch1) **불일치 — 그 자리 센서가 바뀌었습니다.**
```

**지자기 없음** — 자동으로 6축으로 떨어진다. 치명적이지 않지만 방위 드리프트가 커진다.
```
[WARN] [AK8963] 지자기 센서 응답 없음 (상태 추정 시 6축 우회 플래그 유도).
```

**필터 우회 알림** — 현재는 정상 (임시 상태)
```
[WARN] [I2C Driver] ※ 압력 IIR 필터 비활성 (특성화 측정용). 운용 전 원복할 것.
```

**조종기 없음** — 벤치에서는 정상. 2초마다 반복된다.
```

```

## 4. 조종기 버튼

**1틱 = 10 ms** (`/rc/status` 메시지 1개 = 1틱, 실측 100.0 Hz).

- **짧게** = 카운터 4\~99틱 = **0.04\~0.99초**. 실용적으로는 **"약 0.5초 톡 누르고 뗀다."**
  **1초를 넘기면 아무 일도 일어나지 않는다** (짧지도 길지도 않은 구간이라 무시된다).
- **길게** = **정확히 3초**(300틱)에서 **한 번만** 발동한다. `== 300`이지 `>= 300`이 아니라,
  계속 누르고 있어도 한 번만 실행되고 손을 뗄 때 짧은 누름으로도 세지 않는다.

| | 짧게 (0.03\~1초) | 길게 (정확히 3초) |
|---|---|---|
| **btn1** | AUTO / MANUAL 토글 | **대기압 재영점** (공기 중에서만 — 잠기면 거부) |
| **btn2** | 현재 방향을 yaw 0°로 | **지자기 보정 시작** (다시 누르면 조기 종료) |

처리 노드가 나뉘어 있다:

- **btn1 짧게** → `state_estimation_ekf_node` (모드 토글)
- **btn1 길게** → `hydro_estimator_node` (2026-08-21 이관). EKF도 3초 누름을 **감지만** 하는데,
  그 표시가 없으면 손을 뗄 때 짧은 누름으로 오인되어 모드가 제멋대로 토글되기 때문이다.
- **btn2** 양쪽 다 → `state_estimation_ekf_node`

### 눌렀을 때 보이는 문구

```
[INFO] [EKF] 로봇이 자동(AUTO) 모드로 전환되었습니다! (카운트: 3)      ← btn1 짧게
[WARN] [Hydro] 대기압 영점 재포착 시작 (버튼1 롱프레스, 101샘플 약 9초) — 로봇을 흔들지 마십시오.
[INFO] [EKF] 지자기 캘리브레이션 성공 — 새 보정 즉시 적용             ← btn2 길게 완료
```

### 링크가 끊기면 버튼이 255로 온다

nRF는 조종기 링크가 끊기면 버튼값을 `255`로 보낸다. `1 → 255` 전이를 "뗌"으로 오인하면
모드가 제멋대로 바뀌므로, 두 노드 모두 **0/1이 아닌 값은 거부하고 카운터를 리셋**한다.

## 5. 조종기 스틱과 통신 두절

### 스틱 매핑 — `/rc/command` (Quaternion을 그릇으로 재사용)

| 필드 | 의미 | 단위 |
|---|---|---|
| `x` | Roll 목표 | 0.1도 (PID가 ×0.1) |
| `y` | Pitch 목표 | 0.1도 |
| `z` | Yaw 목표 | 0.1도 |
| `w` | 스로틀 | 원시 0\~1171 → PWM 1000\~2000으로 선형 사상 |

### `/rc/status` — `Int32MultiArray[5]`

`[btn1, btn2, vbat1×100, vbat2×100, rssi]` — **전압은 100으로 나눌 것.** RSSI는 dBm.

### 통신 두절 — `-9999` 센티넬

링크가 끊기면 nRF가 **네 채널 전부를 `-9999`** 로, **버튼을 `255`** 로, **RSSI를 `-127`** 로 바꿔 보낸다
(실측 확인). `pid_control_node`는 스로틀 한 칸만 검사하는데, 네 채널이 함께 바뀌므로 문제되지 않는다.

> **`RSSI = -127`은 "신호가 약함"이 아니라 "링크 없음"이다.** 둘을 구분해서 읽을 것.

`pid_control_node`는 두 가지로 잡는다:

1. `rc_throttle_ == -9999` — nRF가 명시적으로 통보
2. **5초 타임아웃** — nRF 자체가 죽어 `/rc/command`가 아예 안 오는 경우

두절이 확인되면 출력은 즉시 **중립**이 된다:

```
[1500, 1500, 1500, 1000]   // 좌서보, 우서보, 요서보 중립 + 추진 정지
```

**기동 직후에도 이 상태다.** `rc_throttle_` 초기값이 `-9999`라, 첫 정상 패킷이 오기 전까지는
항상 페일세이프로 묶여 있다.

> 로그의 `Timeout: 26.7초`는 **임계값이 아니라 경과 시간**이다. 임계값은 5초 고정이다.

### 배터리는 아무도 보지 않는다

`/rc/status[2]`, `[3]`(전압 ×100)을 **구독하는 노드가 하나도 없다.** CSV에도 전압 열이 없고,
저전압 경고를 내는 코드도 없다. **사람이 직접 보지 않으면 어디에도 남지 않는다.**

실측 기준선: **배터리1 = 16.00 V, 배터리2 = 6.05 V**. 이 값은 nRF가 로봇 자체 배터리를 재는
것이라 **조종기 링크가 끊겨도 계속 유효하다.**

```bash
ros2 topic echo /rc/status      # [btn1, btn2, vbat1x100, vbat2x100, rssi]
```
장시간 시험 때는 별도 터미널에 띄워둘 것.

> **⚠️ AUTO 모드에서는 이 페일세이프를 건너뛴다.** 조종기 없이 도는 것이 자율 주행의 정상
> 동작이기 때문이다(`pid_control_node.cpp:147`, `!is_auto_mode_ &&`). **즉 AUTO에서는
> 조종기를 꺼도 로봇이 멈추지 않는다.** 이건 설계 의도이지 버그가 아니다.

## 6. 보정 절차

### 6.1 지자기 보정 — 텀블이 필요하다

**왜 움직여야 하나**: 로봇 몸에 붙은 쇠붙이가 자기장을 휘게 만드는데, 그 왜곡을 재려면
자기장 벡터가 **자세에 따라 그리는 궤적(타원체)** 을 봐야 한다. 한 자세에 가만히 있으면
점이 하나뿐이라 타원체를 그릴 수 없다. 수학적으로 불가능하다.

(자이로 영점이 정지를 요구하는 것과 정반대인 이유가 이것이다. 자이로는 "참값이 0인 줄
아는 상태"에서 출력을 읽는 것이고, 지자기는 "여러 자세의 궤적"을 읽는 것이다.)

**절차**
1. 강철에서 **1 m 이상** 떨어진 자리에서
2. btn2를 **3초** 누른다 (또는 `ros2 service call /calibrate_mag std_srvs/srv/Trigger`)
3. **한 자리에서** 로봇을 여러 방향으로 굴린다. 6면이 각각 위를 향하도록
4. **평평한 스핀만 돌리면 안 된다** — 수직 방향 오프셋을 볼 수 없다
5. 충분히 모이면 자동 종료. 조기 종료하려면 btn2를 다시 3초

**안전장치**: 흩어짐 **8 %를 넘으면 저장을 거부**한다. 기존 파일은 백업된다.
성공하면 EKF가 **즉시 다시 읽는다 — 재시작 불필요.**

**보정 중에는 강제 6축**이 된다:
```
[WARN] [EKF] 지자기 캘리브레이션 중 -> 강제 6축 (완료 시 자동 복귀)
```

> **보정은 장소가 아니라 어셈블리에 묶인다.** 부품을 하나라도 붙이거나 떼면 무효다.
> 하우징을 닫으면 하드아이언이 통째로 바뀐다 — 지난 조립 때
> (−12.3, +23.5, −89.8) → (+9.9, +61.6, −16.1) µT로 완전히 달라졌다.
> **최종 조립 후 반드시 다시 할 것.**

### 6.2 압력 영점 — 자동이다

**켤 때는 버튼이 필요 없다.** 180초 웜업 뒤 자동으로 잡힌다.

btn1 3초는 **공기 중에서 다시** 잡을 때만 쓴다:
- 하우징을 열었다 닫았을 때
- 오래 켜둬서 날씨로 기압이 변했을 때 (시간당 1\~2 hPa = 수심 1\~2 cm)
- 지자기 보정 텀블로 영점이 오염됐을 때

재영점은 **웜업 180초를 건너뛰고 즉시 9초간 수집**한다. 이미 데워진 센서이기 때문이다.

**물에 잠긴 채 누르면 즉시 거부된다** (게이지압 5 mbar ≈ 5 cm 초과):
```
[ERROR] [Hydro] 물속으로 보입니다 (게이지압 29.30 mbar, 약 30 cm) — 대기압 영점을 잡지 않습니다.
```
물속 q 영점은 이 버튼에 없다. 필요하면 `ros2 service call /hydro/zero_q std_srvs/srv/Trigger`.

**거부돼도 쓰던 영점은 그대로 유지된다** — 수심이 끊기지 않는다.

**그 밖에도 거부될 수 있다.** 흔들리거나 산포가 크면:
```
[ERROR] [Hydro] 대기압 영점 포착 실패 — 다시 시도합니다
  ch0: 중앙값 1104.32 mbar 가 [900, 1100] 밖 -> 거부 (물속에서 잡으려는 것 아닙니까?)
  ch1: 산포 2.310 mbar (한계 1.50) -> 거부 (로봇이 흔들리거나 물에 떠 있습니다)
```
거부해도 포기하지 않고 계속 재시도한다.

### 6.3 두 보정을 한 번에 하는 순서 (권장)

텀블이 압력 영점 수집과 겹치면 영점이 오염된다. 1 m만 들어올려도 기압이 0.12 mbar 움직인다.

```
① 켜고 처음 10초 가만히          → 자이로 영점
② 텀블로 지자기 보정 (btn2 3초)   → 끝나면 즉시 적용
③ 로봇을 내려놓고 btn1 3초        → 압력 재영점 (웜업 안 기다림)
④ 9초 가만히
```

재부팅하는 방식(보정 → 재부팅 → 180초 대기)도 되지만 3분이 더 걸린다.

## 7. AUTO 모드

### 들어가고 나오기

**btn1 짧게** 누를 때마다 토글된다. 모드는 별도 토픽이 아니라 **자세 메시지 안에 실려 나간다** —
AUTO일 때 `attitude.x`(roll)에 **+5000**이 더해진다. 세 노드가 `|x| > 2500`으로 각자 해독한다
(`pid_control_node.cpp:78`, `auto_scenario_node.cpp:46`, `data_logger_node.cpp:202`).

### 현재 시나리오 — 6초 주기 반복

| 구간 | Roll | Pitch | Yaw | 스로틀 |
|---|---|---|---|---|
| 0\~3초 | 0° | **+10°** | 0° | 1500 (50 %) |
| 3\~6초 | 0° | **−10°** | 0° | 1500 (50 %) |

**양수 pitch = 코 아래**(항공 규약 반대)이므로 위 시나리오는 3초 숙이고 3초 드는 동작이다.

```
[INFO] [SCENARIO RUN] 진행 경과: 12.3초 (현재 사이클: 0.3초) | 지시 Pitch: 10.0도
```

MANUAL로 돌아오면 시나리오는 중립(스로틀 1000)을 계속 덮어쓴다.

### ⚠️ AUTO 진입 전 확인

- **스로틀이 1500(50 %)으로 즉시 올라간다.** 로봇을 고정했는지 확인할 것
- **조종기를 꺼도 멈추지 않는다** (5장 참조)
- 나오려면 **btn1 짧게** — 조종기가 살아 있어야 누를 수 있다
- **지자기 보정이 유효해야 한다.** 시나리오는 `Yaw = 0°`를 명령하는데, 보정이 나쁘면
  그 "0도"가 북도 출발 방향도 아닌 엉뚱한 방위가 된다. 수동 조종에서는 헤딩 오프셋이
  고정이라 티가 안 나지만 **AUTO에서는 그 오차가 그대로 조타에 들어간다.**
  진입 전 기동 로그의 복각 오류(3장)를 반드시 확인할 것

스로틀은 **1000 → 1500 계단**으로 올라간다(램프 없음). 진입 첫 1틱(≤10 ms)만 1000이고
그 다음 주기부터 1500이다.

> **⚠️ 이 빌드에서 AUTO를 한 번도 눌러본 적이 없다.** 저널 전 구간(8/18\~8/21)에
> "모드로 전환" 0건, 시나리오 실행 0건이다. **첫 진입은 반드시 로봇을 고정하고, 물 밖에서 할 것.**

### AUTO 중 조종기가 끊기면 — 탈출 경로

버튼값이 `255`가 되어 **btn1로 수동 복귀가 안 된다.** 두 가지 방법이 있다:

```bash
pkill -f state_estimation_ekf_node    # ① 권장 — 2초 뒤 respawn 되며 MANUAL로 되살아난다
sudo systemctl stop fish-robot        # ② 전체 정지
```

①이 되는 이유: `is_auto_mode_`는 프로세스 메모리에만 있어서 재기동하면 `false`로 초기화된다.
`/filtered/attitude`에 +5000이 사라지면 PID가 MANUAL로 떨어지고, 그 순간 `-9999` 페일세이프가
살아나 모터가 중립으로 간다. launch가 `respawn=True, respawn_delay=2.0`이라 **약 2초의 공백**만 있다.

## 8. 증상별 진단

| 증상 | 원인 후보 | 확인 |
|---|---|---|
| 자세가 안 나옴 (`/filtered/attitude` 무음) | nRF 무응답 | UART에 바이트가 오는지: `timeout 5 cat /dev/ttyAMA0 \| wc -c` (정상 ≈ 23000/5초) |
| yaw가 이상함 | 지자기 보정 문제 | 기동 로그의 **복각 오류** 확인 |
| 수심이 NaN | 영점 미포착 / 정압 채널 사망 | `/filtered/hydro`의 flags |
| 압력이 고정값으로 굳음 | I2C 버스 잠김 | `[I2C Driver] ... 버스 잠김 의심` |
| 모터가 안 돎 | 조종기 두절 | `[PID Control] ... 통신 두절` |
| RPM이 0 또는 200 단위로 튐 | 정상 | 분해능이 200 RPM이다 |

### 벤치 스크립트를 쓸 때 — `/motor/output`의 두 번째 발행자가 된다

`servo_direct.py`, `servo_hold.py`, `servo_toggle.py`는 **직접 `/motor/output`을 발행한다.**
`pid_control_node`가 살아 있으면 두 발행자가 번갈아 서보를 밀어 결과를 못 믿는다.

```bash
sudo systemctl stop fish-robot     # 또는 최소한 pid_control_node 만 내릴 것
```

`rc_check.py`, `rc_map.py`는 **구독만** 하므로 서비스와 함께 돌려도 안전하다.
다만 셋 다 `CMakeLists.txt`에 설치되지 않아 `ros2 run`으로는 실행되지 않는다:

```bash
python3 ~/ros2_ws/src/fish_robot_pkg/scripts/rc_map.py     # 스틱 매핑 확인
python3 ~/ros2_ws/src/fish_robot_pkg/scripts/rc_check.py   # 조종기->서보 경로 어디가 끊겼나
```

### 유령 발행자 점검 — 측정 전 필수

이 프로젝트에서 가장 비쌌던 함정이다(§7.1). 고아 프로세스가 **삭제된 바이너리**로 계속
돌면서 같은 토픽에 발행해, 두 필터의 출력이 섞인 가짜 결과를 만들었다.

```bash
ros2 topic info /filtered/attitude --verbose | grep -c "Endpoint type: PUBLISHER"   # 1이어야 함
ros2 topic info /sensor/pressure_calibrated --verbose | grep -c "PUBLISHER"         # 1이어야 함
ls -l /proc/*/exe 2>/dev/null | grep '(deleted)'
```

> **`(deleted)`가 나왔다고 곧바로 유령은 아니다.** 서비스가 도는 중에 `colcon build`를 하면
> 실행 중인 노드는 정상적으로 `(deleted)`가 된다. **유령의 표식은 `ppid == 1`(고아)** 이다:
> ```bash
> for p in $(ls -l /proc/*/exe 2>/dev/null | grep '(deleted)' | grep -o '/proc/[0-9]*/' | grep -o '[0-9]*'); do
>   echo "PID $p ppid=$(awk '{print $4}' /proc/$p/stat)"
> done
> ```
> `ppid`가 launch 프로세스면 정상, `1`이면 유령이다. `pgrep -x`로는 안 잡힌다 —
> `comm`이 15자에서 잘리기 때문이다.

**발행자가 2개가 되면 실제로 무엇이 깨지나** — "PID 게인이 틀어진다"는 설명은 **지금은 틀렸다.**
현재 `ki = kd = 0`(P 제어만)이라 제어량은 주기와 무관하다. 실제 피해는 두 가지다:

1. **서로 다른 두 추정기의 자세가 번갈아 PID에 들어간다** — 출력이 두 값 사이에서 떤다
2. `/motor/output`이 200 Hz가 되어 **UART 패킷이 두 배로 나간다**

`I`나 `D`를 살리는 순간 `dt` 생략 때문에 게인 문제도 **그때부터** 진짜가 된다.

## 부록 — 명령어

```bash
# 서비스
sudo systemctl {status,start,stop,restart} fish-robot
journalctl -u fish-robot -f                 # 실시간 (노드 출력은 터미널이 아니라 여기로 간다)
journalctl -u fish-robot -b | head -60      # 이번 부팅 기동 로그

# 수동 실행 — 반드시 서비스를 먼저 멈출 것
# (안 그러면 두 벌이 /dev/ttyAMA0, I2C, GPIO 21을 놓고 다툰다)
sudo systemctl stop fish-robot
source /opt/ros/jazzy/setup.bash && source ~/ros2_ws/install/setup.bash
ros2 launch fish_robot_pkg fish_robot.launch.py

# 상태 확인
ros2 topic echo /filtered/attitude --once      # roll(+5000=AUTO), pitch, yaw
ros2 topic echo /filtered/hydro --once         # [depth, speed, q, q_raw, dP_hydro, static, pitch, flags]
ros2 topic echo /filtered/ekf_status --once    # [0..2]바이어스 [3..5]1σ [10]플래그
ros2 topic hz /sensor/pressure_raw             # ~11 Hz
ros2 topic hz /filtered/attitude               # ~100 Hz

# 서비스 호출
ros2 service call /calibrate_mag std_srvs/srv/Trigger   # 지자기 보정 (재호출 = 조기 종료)
ros2 service call /hydro/zero_atm std_srvs/srv/Trigger  # 대기압 재영점

# 빌드 — 반드시 워크스페이스 루트에서
cd ~/ros2_ws && colcon build --packages-select fish_robot_pkg
```

### 플래그 정상값

| 토픽 | 정상값 | 뜻 |
|---|---|---|
| `EKF_Flags` (`ekf_status[10]`) | **7** | 초기화 + 가속도 + 지자기 적용 (9축) |
| | 35 (=7\|0x20) | 지자기 두절 → 6축 폴백 |
| `hydro flags` (`hydro[7]`) | **0x005** | 육상: 수심 유효 + 대기압 영점 확보 |
| | 0x01F | 물속: + 속도 유효 + q 영점 + 자세 신선 |

### 로그가 남는 곳

| 종류 | 위치 | 자동 정리 |
|---|---|---|
| 텍스트 로그 | **journald** (`journalctl -u fish-robot`) | 있음 (디스크 10 % 한도) |
| ROS2 사본 | `~/.ros/log/` | **없음** — journald와 중복이라 지워도 무방 |
| 데이터 (CSV) | `~/ros2_ws/log_csv/` | 200 MB 회전만, **삭제 안 함** |

CSV 형식은 `docs/csv_format.md` 참조.
