# magneto_cal — 지자기 보정 도구

물고기 로봇의 지자기(AK8963) 하드아이언·소프트아이언을 텀블 + 타원체 피팅으로 구한다.
`fish_robot_pkg` 패키지의 개발 도구다. 로봇에 상주하지 않고, 토픽만 구독하므로
systemd 서비스가 도는 채로 그대로 실행된다.

## 왜 따로 만들었나

내장 캘리브레이션(btn2 롱프레스, `/calibrate_mag`)은 **축별 min/max 중점**을 쓴다. 손으로 돌려
각 축의 진짜 극값에 닿아야만 맞는 방식이고, 실제로 못 닿는다.

2026-08-06에 같은 로봇·같은 배치에서 두 방법을 나란히 채점한 결과:

| | \|m\| | 흩어짐 | 복각 (정답 143°) |
|---|---|---|---|
| 무보정 | 94.4 ± 20.9 µT | 22.1 % | 94.7 ± 51.0° |
| **btn2 (min/max)** | 45.9 ± 17.5 µT | **38.1 %** | 124.7 ± 24.1° |
| **이 도구 (타원체)** | 34.7 ± 1.5 µT | **4.3 %** | **144.5 ± 2.9°** |

**btn2 방식은 무보정보다 나빴다.** 중심이 어긋난 상태에서 소프트아이언 배율(0.953/0.953/1.108)까지
곱하니 그나마 일관되던 자기장을 더 망가뜨린다.

## 쓰는 법

```bash
source /opt/ros/jazzy/setup.bash
ros2 run fish_robot_pkg magneto_cal.py
```

화면의 여섯 자세를 하나씩 잡고, **그 자세 그대로 제자리에서 한 바퀴** 돈다.
로봇을 들고 본인이 도는 게 제일 쉽다. 책상에 놓고 돌려도 된다.

```
  ✅① 평소 자세 (배가 아래)      ████████  371도
  ▶ ② 뒤집기 (배가 위)           ███░░░░░  142도  ← 이 자세로 계속 도세요
    ③ 왼쪽 옆으로 눕히기         ░░░░░░░░    0도
    ...
```

여섯 자세가 다 차면 자동으로 끝나고, 품질 검사를 통과하면
`~/ros2_ws/config/mag_calib_params.txt` 에 저장한다(기존 파일은 `.bak_날짜` 로 백업).

| 옵션 | 용도 |
|---|---|
| `--csv <파일>` | 이미 모은 데이터로 다시 계산. **로봇 없이 오프라인** |
| `--search-axes` | 축 재배치 24가지를 전부 시험 (새 하드웨어일 때) |
| `--dip 143` | 그 지역 복각. 한국 143, 적도 부근 90 |
| `--no-write` | 결과만 보고 파일은 안 건드림 |
| `--mag-topic` / `--imu-topic` | 토픽 이름 변경 |

## 반드시 지킬 것

**한자리에서 돌린다.** 들고 돌아다니면 주변 자기장이 바뀌어 피팅이 오염된다.
철제 책상·PC 본체·스피커에서 1 m 이상 떨어진다.

**최종 조립 상태에서 한다.** 보정이 잡는 것은 **로봇 몸에 붙은** 자성이다. 장소를 옮겨도 그대로
유효하지만(환경 자기장은 몸 기준으로 회전하므로 원의 중심을 옮기지 않는다), **부품을 붙이거나
떼면 무효**다.

**저장 후 `state_estimation_node` 를 재시작한다.** 파일은 노드 시작 시 한 번만 읽는다.

**btn2 롱프레스를 누르지 않는다.** 매번 이 파일을 min/max 방식으로 조용히 덮어쓴다.

## 이 도구가 피해 가는 함정

**① 평평한 회전으로는 보정할 수 없다.** 실측 하드아이언은 93.6 µT인데 그중 89.8이 칩 Z축이다.
수평 회전은 수평 성분(37.8 µT)만 본다. 뒤집지 않으면 나머지는 **구조적으로** 보이지 않는다.

**② 진행도를 자기장으로 재면 안 된다.** 하드아이언이 지구 수평장보다 크면 로봇을 360° 돌려도
자기장 방향은 한 바퀴를 돌지 않는다(실측: **102°만 움직이고 되돌아옴**). 보정하려는 대상으로
진행도를 재는 셈이라, 자세에 따라 즉시 채워지거나 영영 안 채워진다. 이 도구는 **자이로**로 잰다.
자이로는 계산에는 일절 쓰이지 않는다 — 순수하게 "이제 그만 돌려도 된다"는 안내용이다.

**③ 2차식은 데이터를 중심 이동시킨 뒤 풀어야 한다.** 자기장 덩어리가 원점에서 수십 µT 떨어져
있으면 `x²` 항들이 거의 평행해져 정규방정식이 병들고, 반지름이 음수로 나와 실패한다. 평균을 먼저
빼고 풀어 다시 더한다. (합성 데이터 검증: 정답 중심 `[-12, 28, -64]`, 반지름 `[46, 42, 50]` 을
소수점 둘째 자리까지 복원.)

**④ 나쁜 결과는 저장하지 않는다.** 보정 후 `|m|` 흩어짐이 8 %를 넘으면 파일을 건드리지 않는다.
원시 데이터는 성공·실패와 무관하게 항상 `log_csv/tumble_*.csv` 로 남으므로 `--csv` 로 재계산하면
된다 — 다시 돌릴 필요가 없다.

## 축 재배치 판정

복각(자기장과 중력 사이 각)은 그 지역에서 물리적으로 정해진 값이고 **회전 불변량**이다. 따라서
오른손 좌표계 24가지 후보 중 그 값을 일정하게 내놓는 것이 정답이다.

**하드아이언이 클 때는 이 판정이 불가능하다** — 큰 오프셋은 그 자체로 어떤 복각 값이든 만들어낼 수
있다. 그래서 하드/소프트아이언과 축을 **한 데이터에서 같이** 풀어야 하고, 이 도구가 그렇게 한다.

2026-08-06 실측 (`--search-axes`):

```
1. (+y,+x,-z)     복각  144.3 ± 3.0도   ← 현재 코드. 정답
2. (+y,+z,+x)     복각  110.6 ± 23.9도
3. (-x,+y,-z)     복각  119.3 ± 34.8도
```

평균뿐 아니라 **흔들림이 8배 차이**다. 틀린 축은 자세에 따라 복각이 요동친다.
이 결과로 `state_estimation_node.cpp:495-521` 의 `(my, mx, -mz)` 가 확정됐다 —
주석의 유도(MPU9250 다이 정렬)는 전제가 틀렸지만 결론은 맞았다.

## 끝단 검증 — `verify_spin.py`

보정이 끝났으면 **반드시** 이걸로 확인한다. 흩어짐이나 복각이 좋아도 헤딩이 실제 회전을 일대일로
따라가지 않으면 쓸 수 없다.

```bash
ros2 run fish_robot_pkg verify_spin.py 60
```

처음 6초 정지(자이로 바이어스 측정), 그 다음 수평으로 들고 제자리에서 한두 바퀴. 정답 기준은
**자이로를 중력축 둘레로 적분한 각**이다 — 보정하려는 지자기로 진행도를 재는 함정(위 ②)을 피한다.

**자이로 바이어스를 반드시 뺀다.** 이 로봇의 z 바이어스는 세션마다 −0.044 ~ −2.2 °/s로 50배
움직인다. −2.2일 때 빼지 않으면 30초에 66°가 그냥 샌다.

2026-08-06 실측 (66초, 한 바퀴):

| | 회전량 | 비율 | 역행 (0.5초 평활) |
|---|---|---|---|
| 물리 (자이로) | −357.74° | — | — |
| **보정 적용** | **−361.79°** | **1.01** | **7.7°** |
| 무보정 | −1.55° | 0.00 | 102.0° |

**총량만 보면 안 된다. 45° 구간별로 봐야 한다.** 보정 후는 38~52°로 전부 45° 근처지만, 무보정은
구간마다 12~19°로 느리게 가다가 270~315° 구간에서 **−45.1°로 역주행**한다. 못 쓰게 만드는 건 총량이
아니라 이 역주행이다.

**역행은 평활한 뒤에 세야 한다.** 100 Hz에 33 °/s면 한 샘플이 0.33°인데 지자기 잡음이 그보다 크다.
원시 샘플로 세면 좋은 데이터도 3500°가 넘게 나온다.

잔차(자이로 대비)는 **중앙값 2.22°, 95 % 5.87°**이고, 한 바퀴에 **정확히 한 주기인 사인파(진폭
3.58°)** 다. 이건 잔여 하드아이언의 서명이고 역산하면 수평 **1.34 µT** — 타원체 피팅이 남긴 1.5 µT
잔차와 일치한다. 즉 남은 오차는 새 문제가 아니라 예측된 보정 잔차다.

## 알려진 미해결

- **보정 후 `|m|` 가 34.7 µT** 로, 한국의 ~50 µT보다 30 % 낮다. 방향은 맞아 헤딩·자세에는 영향이
  없지만(위 끝단 검증이 비율 1.01로 확인), AK8963의 ASA 감도 ROM이 `i2c_driver_node` 어디에서도
  적용되지 않는지 확인이 필요하다.
- **열 드리프트.** CPU 4코어 부하 *이후* 자기장이 3 µT 이동하고 잡음이 3.7배(σ 0.68 → 2.64)로
  늘었다. 전류가 아니라 열이 센서에 도달한 것으로 보인다. 3 µT ≈ 헤딩 8°이므로 달성 가능한
  정확도의 천장일 수 있다. 위 잔차 3.1°는 냉각 상태에서 잰 값이다.
